GO B+ TREE / LESSON 05

5. キーを削除する

葉から1件取り除き、最小数を割ったかを確かめる

Delete(key) は対象のペアを取り除き、後ろのペアを左へ詰めます。削除できたかどうかを ok で返します。存在しないキーなら、木を変更せず false です。

降下時の安全条件は「子の個数が最小数より多い」です。図の最小数は2件なので、3件以上あれば1件削除しても下限を割りません。2件しかない子へ降りる場合は、借用やマージに備えて親を保持します。

図の読み方　最大4件・最小2件に縮めたモデルです（Goは510件・255件）。「次へ」で1場面ずつ進めてください。図とコードはその場面の処理を終えた状態を示します。色付きの枠は注目箇所、R/Wバッジはこの操作が保持するページラッチです。

1. 70を削除する

右端の葉 [50,60,70] は3件。削除後も2件残るので、兄弟や親の内容を変える必要はありません。

2. 存在しない999を削除する

降下は行いますが、leafFindPosのfoundがfalseなのでペアを取り除きません。

分離キーは毎回「右の最小値」に直すのか

いいえ。この実装が守る条件は 左の最大キー < 分離キー ≤ 右の最小キー です。右側の最小キーを削除しても、この条件を守っていれば分離キーを残せます。借用でキーが境界をまたぐ場合には、分離キーを更新します。

ルートは最小数の制限の例外です。空の木も、0件の葉ルート1枚として表します。
