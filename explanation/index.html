0. 概要

github.com/ryogrid/concurrent-bp-tree-tutrial/bptree は、 古典的 B+ 木を単一ファイルに永続化する Go の key-value ストア。key / value は int64 固定、ページサイズ 8KiB、WAL なし。並行性はノード単位のラッチ (読み書きロック) + ラッチクラビングで実現し、木全体をロックしない。

API は Put / Get / Delete / RangeScan(start,end)。 全操作はアトミックに見え（対象リーフのラッチを保持したまま変更）、 木の接続関係はすべてページIDでファイルに永続化される —— メモリ上にポインタの木は存在しない。

1. ファイルフォーマット

DB ファイルは 8KiB ページの配列。先頭ページはメタデータ専用で、 それ以降がノードページまたはフリーリストページ。DiskManager (disk.go) が固定サイズの読み書きとファイル伸長を担う。

2. ノード構造

すべてのページを int64 スロット (1024個/ページ) として扱う。 リーフは (key,value) 対を昇順に持ち nextLeafPID で右兄弟へ繋ぐ。 内部ノードは key と子ページIDを交互に持ち、key[i] は 「child[i+1] 側の最小キー」を表す古典的セパレータ。

3. Get: ルート→リーフ探索

rootMu.RLock でルートページIDを読み、ルートを R ラッチ。 あとは子をラッチしてから親を外す (クラビング) で葉まで降り、 葉内を二分探索。ロックするのは通路上のノードだけ。

4. Put とスプリット

書き込みは W ラッチで下降。安全な子（分裂しない = count < Max）なら 祖先のラッチを即解放 —— これがクラビングの核心。葉が満杯なら 511 エントリのスクラッチ配列で 255/256 に分割し、右ノードを新規ページに 割当ててから分離キーを親へ伝播。親も満杯なら連鎖分裂し、 ルートまで達すれば新ルートで高さ+1。

5. Delete: 借用とマージ

葉から削除して count < Min になれば兄弟と調整。右兄弟が余裕 (>Min) あれば最小要素を借用して親の分離キーを更新。無ければ 右を自分に吸収するか、自分が右端なら自分を左兄弟に吸収。 左兄弟の W ラッチだけはロック順序に逆らうので TryLock + 操作全体の再試行でデッドロックを回避する。ルートが 0 キー内部ノードに なれば高さ-1。

6. ノード単位の排他制御: ラッチクラビング

ロック順序は「親→子、兄弟は左→右」。読みは R ラッチをカップリング （次を取ってから前を放す）。書きは W ラッチで降り、安全な子が 見つかった時点で祖先を全部解放するので、実際に同時保持するのは 「まだ分裂/併合し得る部分木」のみ。スキャンの左→右カップリングと 左兄弟ラッチ取得が衝突し得るため、そこだけ TryLock+再試行。 opSlots セマフォが同時操作数を 20 に絞り、 256 フレーム枯渇による待ちデッドロックを構造的に防ぐ。

7. バッファプール

256 フレームの固定配列 + pageID→frame テーブル。 fetch はヒットなら pin++ して即返却。ミス時は pin=0 のフレームから LRU (最小 lastUsed) を選び、 dirty なら先にディスクへ書き戻してから読込。全フレームが pin 中なら ErrNoFreeFrame で呼び出し側が再試行する。 不変条件は 「ラッチを持つフレームは必ず pin 済み」 「Unpin はラッチ解放の後」。

8. RangeScan: 葉の水平走査

降下は Get と同じ R クラビング。開始葉で start 以上の 最初の位置を二分探索し、k > end またはチェーン終端まで 順に収集。次葉へはR ラッチをカップリング（次を R してから現在を 解放）するので、走査中の分割・併合にキーを取りこぼされない。 各葉の到達時点での内容を返すカーソル一貫性で、スナップショットではない。
